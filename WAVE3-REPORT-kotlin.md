## What was deleted and why it was safe

**Dead code**
- `AuqwExpoModule.streamErrCode` — private helper superseded by the
  `streamKind` seam map; zero call sites after consolidation.
- `AuqwNsd.releaseLock(executor)` — single-caller private whose whole
  body is already covered by `stopBrowse()` once `discovery` is nulled
  first (the catch site already did that). Verified: `stopBrowse`'s
  extra steps (generation bump, empty-queue clears) are no-ops on the
  never-registered listener path.
- `AuqwSyncSockets.acceptThread` — write-only field (three writes, zero
  reads). The accept daemon exits when `stopListening()` closes the
  `ServerSocket`; the field tracked nothing.
- Unreachable `try { q() } catch (e) { throw e }` re-throw wrappers in
  `AuqwTagReader.enumerate` / `AuqwWaveformPeaks`.

**Over-abstraction collapsed**
- `lastOnline`/`lastMetered` volatile pair → single `Pair` snapshot
  (more atomic, same edge-detection semantics).
- Per-doc batching (`try { each } catch { Log.w; null }`) duplicated in
  `fingerprint`/`readTags` → one `perDoc` helper; identical log strings.
- Reader-thread spawn duplicated at accept/connect sites → `spawnReader`.
- Codec/extractor/spill `try { x() } catch { Log.i }` triples → `quiet`.
- Head/tail `FileChannel` fill loops → `fill` (same short-read semantics).
- `sameUid` for the binder's identical UID gate on `player()`/`service()`.
- `QUEUE_COMMANDS` hoisted to the companion — was duplicated between the
  command-advertise and command-route sites.
- `failedBundle` for the identical `type/kind/message/attempt` failure
  bundle in `requestOutcomeBundle`/`prepareOutcomeBundle`.
- `remote-next`/`remote-previous` dispatch arms duplicated across
  `onPlayerCommandRequest`/`onMediaButtonEvent` → one command map + one
  dispatch-then-consume block each.

**Verbosity / guard merges (all behavior-identical)**
- `play()`: local/stream attach tails merged — the permission request +
  `null` tail was duplicated under an early `return@Coroutine`.
- `driveTransition`: `idx<0`/`pos<0` guards folded into
  `order.indexOf(items.indexOfFirst{...})` — `indexOf(-1) == -1` hits
  the same return.
- `installProjection`/`stop`/`releaseStream` now use `detachPlayer`
  (clearAttach+stop+clearMediaItems); `releaseAbandonedAttach` and
  `dropArmedMove` reordered past the player calls — verified they touch
  only the latch/registry/host, and every player listener no-ops on a
  cleared join.
- `errorKind` cause-walk → `generateSequence<Throwable>` + `firstOrNull`.
- `seamError` arms reordered (`!is Failed` first) + `INVALID_RESPONSE_KINDS`
  set — kind sets are disjoint, mapping identical.
- `validateProjection` guards → single-line `bad(...)` calls; dropped a
  `p.order.isNotEmpty()` pre-check subsumed by the two conditions.
- `ByteArrayMediaDataSource.readAt`: `position >= size` guard subsumed by
  the `n <= 0` check; `position < 0` kept (negative offsets crash
  `arraycopy`).
- NSD resolve queue: `releaseLock` deletion also removed a stray
  `ExecutorService` import; `stopBrowse` reuses the same teardown.
- `index.ts`: every delegation wrapper `export function f(...) { return native.f(...) }`
  → single-line body; `seam.x?.(...) ?? seamUnavailable('x')` kept
  verbatim (the 'unavailable' coded-error contract on iOS is load-bearing —
  not collapsed into truthiness). `syncRandomBytes` keeps its throw path
  via `seamThrow` (a `never` helper — `??` can't throw directly).
- `ErrorKind`/`PlaybackState` unions and doc-free event types compacted
  to multi-member lines; every per-field doc comment kept.
- `hasTagReader`/`hasSyncSocket` keep `typeof x === 'function'` (not
  `!= null`) — the check discriminates absent-vs-present members on the
  Partial seam.

## Deliberately NOT touched

- `android/.../uniffi/auqw_mobile_bindings.kt` (3902 LoC) — generated
  UniFFI bindings; regenerated by `tooling/build-android-bindings.sh`.
- `modules/auqw-expo/ios/**` — shard scope note limits this shard to
  `android/src` + the ts shim; `AuqwExpoModule.swift` left for the iOS
  side.
- **Dormant pairing surface**: Kotlin `syncListen`/`syncListenStop`/
  `syncLocalHosts`/`syncAdvertise`/`syncAdvertiseStop`/`syncBrowse`/
  `syncBrowseStop`/`syncDeviceName` (+ `AuqwNsd`, the listen half of
  `AuqwSyncSockets`, `onSyncSocketAccepted`/`onSyncDiscovery` events)
  have no `index.ts` wrappers yet — `auqw-expo-surface.ts` declares them
  optional and adapters gate on `=== undefined`. That is an in-flight
  slice-4 feature explicitly documented as "no JS wrapper yet", not
  provable dead code. Kept intact.
- `consumer-rules.pro` — the comments document a real R8 `@FieldOrder`
  crash; removing them loses why the `-keep`s exist.
- NSD resolve-queue "skip lost-marked entries" loop — deliberately not
  rewritten as `removeAll`/`firstOrNull`: dropping the whole run of
  stale entries changes re-found duplicate-resolve behavior.
- `AuqwDownloadService` (117) — after one two-line merge it is at its
  floor: lifecycle + notification builder + honest-restart comment.
- Doc comments: kept wherever they state contract/ordering invariants
  (thread confinement, event ordering, honest-unavailable semantics);
  only redundant restatements were dropped.
