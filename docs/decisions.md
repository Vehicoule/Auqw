# Decisions

Statuses: **Decided**, **Deferred**, **Open**. Each row carries its
rationale and the condition that would reopen it.

## Capability surface

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| `catalog.suggest` joins ABI 0.3.0 — keystroke query completions (`{input, limit?}` → `{suggestions: string[]}`) | Decided | Typing fetched full catalog pages per keystroke — heavyweight, slow, and the ranking varied per catalog provider. Completions are one small response, provider-independent, and typo-corrected upstream (predecessor app's `get_search_suggestions` model). | If completions prove consistently worse than live results, revisit; commit path unchanged. |
| `catalog.suggest` has no settings slot — it routes automatically over declaring providers | Decided | Suggestions are provider-independent by design: whichever loaded provider declares the capability serves the draft pane (first declarer, registration order). A per-slot choice would fragment the typing surface without benefit. | If a second declarer lands and ordering matters, introduce routing policy in this log first. |
| Typing no longer runs `catalog.search` — results commit on Enter or a suggestion tap | Decided | Removes per-keystroke catalog load; the committed query is also what caches and recents record, matching what the operator actually searched for. | If users need live results while typing, gate behind a setting — default stays suggestions-first. |
| `stream:read` stays a parked demand read; decorative consumers use `stream_peek` — a serve-only positional read (`bytes` = committed hit, `[]` = confirmed EOF, `None` = unfetched hole) that queues no fetch-through and never parks | Decided | A parked `stream:read` outlives any caller-side timeout, and its queued demand outranks the player's own (demand serves min position first) — a decoration can stall playback. Rather than retract demand with a per-read cancel (`requestId` + session cancel = real contract work), the peek has no demand to retract: abandonment is local — the poll loop just stops polling. Android binds it as `streamPeek` for waveform peaks; `provider:'local'` handles never reach the seam — they decode straight off the file/content URI. The desktop port keeps its deadline-abandon until it adopts the same seam call. | If a decorative consumer needs pull-through (a hole it must fill rather than abandon), or the desktop port shows the same demand reordering measurably, revisit — request-scoped cancel on `stream:read` is the fallback shape. |

## Playback

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Shuffle deals a play order, not a queue order: `QueueProjection.order` carries a permutation of item indices the cursor walks — dealt at toggle-on as the canonical prefix through the cursor + uniformly shuffled successors | Decided | Canonical `items` (and the persisted queue) stay untouched, `previous` keeps real history, and the strict immediate-successor legality check on `queue-transition` survives — a random-next rule would have to accept any target. Mirrors ExoPlayer's ShuffleOrder model. Mutations reconcile the deal: removed occurrences drop out, enqueued ones insert at uniform random positions behind the cursor's dealt position, and dealt successors never reshuffle. `repeat=one` still replays the cursor item; `repeat=all` wraps the dealt ends (tail→head on next/ended, head→tail on previous); a lone item self-wraps into a restart. The queue list keeps showing canonical order. | If "up next" must display the dealt order, or a random-next mode is requested, revisit here first. |

## Presentation

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Waveform peaks extract client-side on desktop AND Android — a `PeaksPort` pulls the playing stream's own bytes and decodes them (WebAudio on web; `MediaExtractor`+`MediaCodec` in `modules/auqw-expo` on Android); iOS keeps the seeded pattern. The contract carries asymmetric pairs — `peaks?: {up, down}[]`, not `number[]` — and extraction/normalization share one implementation: raw per-window magnitudes (`PeakWindow`) reduced by `normalizePeakWindows` (5th–95th percentile → 0.05–1.0 → γ1.2) on the JS side for both platforms, so the native extractor stays a dumb decode+bucket. | Decided | Peaks are pure decoration — a provider-carried amplitude field would entangle every guest plugin's contract for pixels no behavior trusts. The open stream handle already owns the bytes, so the extraction is free bandwidth and zero wire surface; on Android non-demanding `streamPeek` positional reads feed an in-memory `MediaDataSource` — only already-committed bytes are served, a peek queues no demand, and a cancelled sweep leaves nothing competing with playback — while `provider:'local'` handles resolve to their file/content URI and decode straight off disk under the same `maxBytes` extraction cap (the resolved length checked up front, or the consumed-byte bound when it can't be resolved). Local decoded PCM spills to a cache file the bucketer memory-maps rather than a whole-buffer heap copy, so peak allocation stays bounded next to the player. Pairs carry the stereo L/R split (mono: positive/negative half-wave energies) so the bars read organic rather than mirrored. | If iOS gains a decoder-backed path (AVAssetReader in the module) or a provider ships peaks essentially free, revisit — the renderer contract accepts either source. |
| UI typeface is Inter (400/500/700 via `@expo-google-fonts/inter` on mobile, `Inter → ui-sans-serif → system-ui` on web/desktop); JetBrains Mono dropped, along with the "type is monospaced" Omarchy rule | Decided | Monospace read terminal-like rather than music-player; owner directed a Mistral-style sans shell (2026-09). Inter ships through the same bundled-google-fonts mechanism that carried JetBrains Mono — dependency swap, not a new mechanism. | If Inter's metrics break dense metadata/duration columns, revisit with `fontVariant: ['tabular-nums']` or a numeric-only mono fallback. |
| Settings `theme` gains `'adaptive'` — the `ThemeSourcePort` contract is `{scheme, palette?}` pushed over `theme:events`/`theme:subscribe`; `chrome:scheme` widens to `{scheme, canvas?, symbol?}`; SQLite `settings` rebuilds (schema v8) to admit the value | Decided | Scheme sources shipped per design.md: Electron main owns file watchers (Omarchy colors.toml, KDE kdeglobals) and the GNOME portal accent poll, refcounted on renderer subscription so platforms only pay while `adaptive` is selected; Android reads `system_accent*`/`system_neutral*` stops via auqw-expo, iOS stays flag-only. Palette polarity follows `bg` rather than the OS flag — the palette is the source of truth. | If a source emits a palette that should follow the OS flag instead of its own bg luminance, revisit the polarity rule; win32/darwin `systemPreferences` accent path is written but unverified on real hardware. |
| `react` joins `@auqw/ui-shared` as a peer dependency (`*`) — `shell.ts` hosts the shells' shared hooks (`useSerializedWrite`, `useOverlayStack`, `useSmoothedPosition`) | Decided | The hooks were duplicated verbatim across both app shells; hoisting them is the point of the package. A peer — not a hard dep — keeps each app's own React copy authoritative: a second resolved React under the hoisted linker would break hook dispatch. The pure cores (`createSerializedWrite`, `overlayReducer`) stay dependency-free for node-side tests. | If a non-React consumer needs the pure cores and tree-shaking can't keep `react` out of its graph, split `shell.ts` into a react-free module and a hooks module. |

## Playback

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Handle-keyed stream ops (`stream:serve-url|open|read|close|release|marks`) report a dead registry session as `released`; session re-prepares on dead-handle kinds from transport calls AND async `failed` statuses (the element's probe path), while a dead-handle pause reports ok | Decided | Serve-url sessions detach on pause (the last range conn ends) and the reaper evicts them past the 120 s TTL, so a long pause outlives the stream. `not-found` there is dead-resource semantics, not malformed input: mapping it to `released` lets session re-prepare from the queue's persisted position instead of `markUnplayable` + 0:00 reset. DOM-only ops (seekTo/pause on the web player) never touch IPC, so the dead URL surfaces as an async media error — the player probes handle liveness (`stream:marks`) before labeling it transient. | If a handle-keyed op gains a not-found source that is genuinely caller error (e.g. bad arg shape), split that slug back out. |
| Playback resolve+prepare warms ahead of the tap: `PlayerPort.prewarm(provider, sourceRef)` mints one advisory, unattached registry session a same-key `prepare` adopts (registry `adopt_reusable` + host-side fast path that skips the guest invoke); rows the user can reach warm their mappings through a serial candidates pass — up to 9 surface-handed ids or `TrackMetadata` rows per `session.prewarm()` plus the dealt window behind the cursor while playing, deduped by a 64-entry seen-LRU; a track row whose catalog provider differs from playback candidates-resolves into the stream warm's `(provider, ref)` key directly — no mapping or pin commits, since no recording exists to land them; a fresh surface row (hand or resolved backlog) outranks the dealt successor under playing — the visible page is the likelier tap — and each `prewarm({tracks})` hand replaces the visible key set, so a match resolved for a page that left view is discarded and unseen rather than minting over what is on screen | Decided | TTFS: the tap's resolve+mint latency is already spent when the finger lands (the predecessor's visible-streams LRU model), without the media element, operation generations, or attach lifecycle being touched. Speculation is honest work only — gated on `prefetch` + online + unmetered, cancelled on connectivity/settings flips and real playback intent, and a row torn down mid-flight loses its seen mark (and surface id is requeued) so the restarted pass retries it, ambiguous matches park on the row rather than opening a speculative review, and the seen-LRU plus one-warm-slot bound both the memory and the wire cost. Real intent never pays a duplicate: an in-flight row warm is adopted by the attempt (its automatic mapping + pin are exactly what the attempt would write) and an in-flight stream warm coalesces in the registry — the warm request's host-side ownership slot transfers to the attempt so `cancelPrepare` can't kill the adopted handle. | If measured TTFS shows warms rarely adopted (taps land outside the window/surface sets), or the dealt-window heuristic costs more resolve traffic than it saves, revisit the want derivation and window size here first. |

## Sync & settings

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| `artworkCacheBytes` stays a mobile-only settings row — desktop omits it | Decided | Mobile's `expo-artwork` adapter maintains a real bounded on-disk cache the budget row genuinely controls; the desktop renderer draws artwork through Chromium's `<img>` pipeline + HTTP cache and has no application artwork store to bound. A desktop row would dead-end, so it filters out (like `localSupported:false` rows stay visible-but-disabled on iOS, this one is absent — the capability doesn't exist, rather than being gated). | If desktop gains an app-level artwork cache (e.g. a bounded `auqw-art` store beside downloads), un-filter the row and wire the picker. |
| Mobile clipboard exchange uses React Native core `Clipboard` — no `expo-clipboard` dependency | Decided | The surface needs only `getString`/`setString` for pairing payloads and delta docs (plain text). RN 0.86 still ships and types the deprecated core module; adding expo-clipboard would be a new dep for two calls. | If RN removes the module from core or expo-clipboard lands for another feature, swap the two call sites (both in `App.tsx`). |
| The desktop `sync` settings row navigates to the inline sync section — scroll + focus — rather than a separate screen | Decided | Desktop already carries the full sync surface inline (status, pair, devices, delta exchange); a second route would fork pairing/mint state for zero gain. Mobile keeps its dedicated overlay (no inline panel on that screen — the row pushes it). | If the settings screen splits into routes, or sync grows enough surface to need its own desktop route, revisit. |
| Add-to-playlist is a first-class `TrackRow` affordance on desktop — a visible-on-hover/focus `list-plus` button beside the row-actions menu | Decided | design.md's shared row anatomy lists `add-to-playlist` on the row itself; it previously lived only inside the right-click actions sheet. The button reuses the same picker target (`setPickerFor`) so both entries land identically; keyboard users reach it via Tab (the button is focusable inside the row). | If row density or hit-target review pushes it back to the menu, this row changes — design.md row anatomy then needs the same edit. |
