# Decisions

Statuses: **Decided**, **Deferred**, **Open**. Each row carries its
rationale and the condition that would reopen it.

## Capability surface

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| `catalog.suggest` joins ABI 0.3.0 — keystroke query completions (`{input, limit?}` → `{suggestions: string[]}`) | Decided | Typing fetched full catalog pages per keystroke — heavyweight, slow, and the ranking varied per catalog provider. Completions are one small response, provider-independent, and typo-corrected upstream (predecessor app's `get_search_suggestions` model). | If completions prove consistently worse than live results, revisit; commit path unchanged. |
| `catalog.suggest` has no settings slot — it routes automatically over declaring providers | Decided | Suggestions are provider-independent by design: whichever loaded provider declares the capability serves the draft pane (first declarer, registration order). A per-slot choice would fragment the typing surface without benefit. | If a second declarer lands and ordering matters, introduce routing policy in this log first. |
| Typing no longer runs `catalog.search` — results commit on Enter or a suggestion tap | Decided | Removes per-keystroke catalog load; the committed query is also what caches and recents record, matching what the operator actually searched for. | If users need live results while typing, gate behind a setting — default stays suggestions-first. |
| Playlist-wide download (`onDownloadAll`) reaches desktop — the entity screen's download control requests only MISSING entries | Decided | Mobile already shipped the affordance; desktop had the same `DownloadManager.request` path and the same partial-state ambiguity (a playlist read 'partial' forever when held bytes couldn't be told apart from unplayable rows). Requests filter by byte-ownership (`downloads.fileFor` / local `uriMap`), never the playback-capability probe — `localPlaybackFor` answers 'can the player attach these bytes', not 'does the ledger hold them', and probing it would re-request stored tracks and delete their files on a changed mapping. | If request scope should widen (e.g. re-fetch on a changed mapping), decide the ledger's replace semantics here first. |
| `stream:read` stays a parked demand read; decorative consumers use `stream_peek` — a serve-only positional read (`bytes` = committed hit, `[]` = confirmed EOF, `None` = unfetched hole) that queues no fetch-through and never parks | Decided | A parked `stream:read` outlives any caller-side timeout, and its queued demand outranks the player's own (demand serves min position first) — a decoration can stall playback. Rather than retract demand with a per-read cancel (`requestId` + session cancel = real contract work), the peek has no demand to retract: abandonment is local — the poll loop just stops polling. Android binds it as `streamPeek` for waveform peaks; `provider:'local'` handles never reach the seam — they decode straight off the file/content URI. The desktop port keeps its deadline-abandon until it adopts the same seam call. | If a decorative consumer needs pull-through (a hole it must fill rather than abandon), or the desktop port shows the same demand reordering measurably, revisit — request-scoped cancel on `stream:read` is the fallback shape. |
| `stream_probe` joins the stream seam (registry `probe`, host-surface `stream_probe`/`stream_probe_blocking`, napi `streamProbe` on the inner runtime, uniffi `stream_probe`, desktop `stream:probe` → `StreamProbeResult{data,total,eof}`): a peek-first bounded positional read — a committed hit serves like `stream_peek`; on a hole + `fetch:true` it drives ONE ranged GET through the session's own `Fetch` (the minted URL/headers path) sized `min(max_len, chunk_bytes)` and commits the bytes into the sparse store so playback serves them free; pump cooldown/429 maps `RateLimited`, 403 `Expired`, 416/`!EOF` `eof:true`; `fetch:false` degrades to exactly a peek. The IPC boundary caps `maxLen ≤ 1 MiB` | Decided | The waveform's sampled extraction needs bytes at arbitrary offsets a demand read would serialize behind the player's own queue (demand serves min position first) and a peek cannot produce at all. The probe bypasses the demand queue but reuses the minted identity, so each probe is one WAN round-trip that doubles as speculative fill — every probed range lands in the store `stream:read` would eventually have fetched. It stays bounded and cancellation-free like the peek: a probe job abandons between calls, there is no mid-fetch retract contract. | If probes prove to need mid-fetch cancel, or probe-driven fills measurably starve the player's own demand, revisit — a demand-priority split or request-scoped cancel is the alternative shape. |
| Desktop download fetches ride `transfer:fetch*` utility channels — `transfer:fetch` answers `{status, headers}` for a GET, `transfer:fetchBody` streams the body once (8 MiB cap, base64), `transfer:fetchAbort` cancels a parked request idempotently; Node `fetch` beside the transfer sinks, ≤3 manual redirect hops re-validated https-only with the caller's headers verbatim, literal private/loopback targets refused on every hop, a 120 s backstop reporting `transient` | Decided | The renderer's CSP (`connect-src 'self' http://127.0.0.1:*`) forbids https outright and Chromium drops the forbidden `User-Agent` — a minted download URL was unfetchable from the renderer by construction, so downloads failed before the first byte. The utility already owns the files those bytes land in; fetching beside the sinks keeps the wire leg inside the trust boundary and sends minted headers verbatim, while the private-host refusal keeps the bridge from reaching past the renderer's own CSP boundary toward loopback/LAN services. A head/body pair is single-use and abort-addressable — a cancelled download can't double-read a stream or leak a socket. | If the renderer's connect-src ever needs https for another reason (the pump boundary argues it shouldn't), or a download needs a streamed body above the cap, revisit the channel shape here first. |

## Playback

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Shuffle deals a play order, not a queue order: `QueueProjection.order` carries a permutation of item indices the cursor walks — dealt at toggle-on as the canonical prefix through the cursor + uniformly shuffled successors | Decided | Canonical `items` (and the persisted queue) stay untouched, `previous` keeps real history, and the strict immediate-successor legality check on `queue-transition` survives — a random-next rule would have to accept any target. Mirrors ExoPlayer's ShuffleOrder model. Mutations reconcile the deal: removed occurrences drop out, enqueued ones insert at uniform random positions behind the cursor's dealt position, and dealt successors never reshuffle. `repeat=one` still replays the cursor item; `repeat=all` wraps the dealt ends (tail→head on next/ended, head→tail on previous); a lone item self-wraps into a restart. The queue list keeps showing canonical order. | If "up next" must display the dealt order, or a random-next mode is requested, revisit here first. |
| `provider:'local'` on desktop attaches `file://` URIs directly on the audio element — the renderer mints `lf-*` handles keyed to the URI (the mobile adapter's `lf-*` convention: no seam, no new protocol, no pump lease); `localPlaybackFor` answers the real `createLocalPlayback` probe | Decided | The session already routed owned URIs to `provider:'local'` prepares — only the attach leg was missing. A `file://` element source is the simplest route that plays: Chromium decodes and seeks the file with native random access, so no ranged IPC, custom scheme, or utility round-trip is needed. `media-src` admits `file:` next to `'self'`; ownership vs attachability stays split (`fileFor`/`uriMap` for ownership, the probe for attach). The reported mime derives from the shared extension table (`shared/audio-mime.ts`, hoisted from the utility's tag map), then the download ledger's recorded mime for extensionless `dl-*` names, then `audio/*`. | If a container Chromium can't decode must play (`.ape`/`.dsf`/`.wv` are admitted by the scanner's table but not Chromium), or a platform webSecurity rule blocks `file://` element loads, revisit — the fallback shape is a `stream:*`-shaped file pump feeding the existing loopback/MSE attach. |
| A `file://` URI mints an `lf-*` handle only through `local:resolve` — the utility's realpath + grant-confinement gate (`allowedLocalPath`: realpath'd path must sit under the media dir or a `local_sources` tree root, picked-file roots matching exactly); a null answer fails the prepare `unavailable`. Byte consumers that can't use the element (waveform peaks on `lf-*` handles) ride `local:read` — the same gate, positional ranged read, base64 out, empty at EOF | Decided | The renderer's lexical `file://` string can't realpath (no fs), and confining at index time leaves the TOCTOU gap a post-scan symlink swap exploits — the check has to run at attach time, in the process that owns the filesystem. `local:resolve` answers the re-keyed (realpath'd) URI so the element attaches exactly the path the gate approved; `local:read` exists because Chromium `fetch()` cannot read `file://` and `lf-*` handles carry no seam session for `stream:read`. Both are args-guarded like every `local:*` channel (bounded URI, `maxLen ≤ 1 MiB`). | If peaks adopt the mobile `stream_peek` semantics for local files too (cache-file spill, memory-map bucketing), or confinement gains a third root kind (e.g. session-picked single plays), extend the gate here. |
| Handle-keyed stream ops (`stream:serve-url|open|read|close|release|marks`) report a dead registry session as `released`; session re-prepares on dead-handle kinds from transport calls AND async `failed` statuses (the element's probe path), while a dead-handle pause reports ok | Decided | Serve-url sessions detach on pause (the last range conn ends) and the reaper evicts them past the 120 s TTL, so a long pause outlives the stream. `not-found` there is dead-resource semantics, not malformed input: mapping it to `released` lets session re-prepare from the queue's persisted position instead of `markUnplayable` + 0:00 reset. DOM-only ops (seekTo/pause on the web player) never touch IPC, so the dead URL surfaces as an async media error — the player probes handle liveness (`stream:marks`) before labeling it transient. | If a handle-keyed op gains a not-found source that is genuinely caller error (e.g. bad arg shape), split that slug back out. |
| Playback resolve+prepare warms ahead of the tap: `PlayerPort.prewarm(provider, sourceRef)` mints one advisory, unattached registry session a same-key `prepare` adopts (registry `adopt_reusable` + host-side fast path that skips the guest invoke); rows the user can reach warm their mappings through a serial candidates pass — up to 9 surface-handed ids or `TrackMetadata` rows per `session.prewarm()` plus the dealt window behind the cursor while playing, deduped by a 64-entry seen-LRU; a track row whose catalog provider differs from playback candidates-resolves into the stream warm's `(provider, ref)` key directly — no mapping or pin commits, since no recording exists to land them; a fresh surface row (hand or resolved backlog) outranks the dealt successor under playing — the visible page is the likelier tap — and each `prewarm({tracks})` hand replaces the visible key set, so a match resolved for a page that left view is discarded and unseen rather than minting over what is on screen; newer hand kinds extend the same space — `prewarm({occurrenceIds})` names a set of queue rows (an already-resolved row mints straight from its stored `selectedRef`, an unresolved row resolves then mints as an `o:`-keyed surface entry evicted when its occurrence leaves the queue — the on-screen up-next page uses it, refined live by the list's viewability reports as the viewport moves), `prewarm({focus})` is one newest-wins slot the row-intent debounce feeds for hover/focus/touch-down gestures ({occurrence | recording | track}; a recording focus may carry the row's own pin — playlist entries pass their `selectedRef` resolved through the same preference rule as play, so the warm lands on the ref the tap would pick; a focused occurrence's pending resolve keys `f:o`-namespaced so the next focus hand kills it and a stale result never displaces the row under the finger), and `enqueueRecording` re-hands each committed row's occurrence id so a just-enqueued tap adopts instead of resolving cold; the stream warm's queue-side want covers every settled stretch (buffering/playing/paused) with the row `next()` would land on — first unmarked dealt successor, head-wrapped under `repeat=all` — plus the parked cursor row itself while a paused queue sits idle (a cursor moved while paused, a restored session), since its resume press is that row's attempt; warms minted into dead time (URL inside the attach margin, flagged or removed row, queue-mode flip) are cancelled/released at want-re-eval or adoption, never sat out on the 120 s TTL | Decided | TTFS: the tap's resolve+mint latency is already spent when the finger lands (the predecessor's visible-streams LRU model), without the media element, operation generations, or attach lifecycle being touched. Speculation is honest work only — gated on `prefetch` + online + unmetered, cancelled on connectivity/settings flips and real playback intent, and a row torn down mid-flight loses its seen mark (and surface id is requeued) so the restarted pass retries it, ambiguous matches park on the row rather than opening a speculative review, and the seen-LRU plus one-warm-slot bound both the memory and the wire cost. Real intent never pays a duplicate: an in-flight row warm is adopted by the attempt (its automatic mapping + pin are exactly what the attempt would write) and an in-flight stream warm coalesces in the registry — the warm request's host-side ownership slot transfers to the attempt so `cancelPrepare` can't kill the adopted handle. | If measured TTFS shows warms rarely adopted (taps land outside the window/surface sets), or the dealt-window heuristic costs more resolve traffic than it saves, revisit the want derivation and window size here first. |
| Update checks egress only to `api.github.com` — the releases LIST endpoint (`/releases/latest` 404s while every release is a prerelease), once per boot plus manual from settings; install is per-platform: desktop opens the release page over a `github.com/Vehicoule/Auqw/releases` allowlist (no updater infra ships — `.blockmap` assets stay excluded), Android downloads the APK and fires the `ACTION_VIEW`/`vnd.android.package-archive` install intent through a FileProvider (`REQUEST_INSTALL_PACKAGES` joins the module manifest), iOS/web open the release page | Decided | The check is a real network egress the desktop renderer CSP forbids (`connect-src 'self'`), so it runs in main and crosses `update:*` IPC as validated snapshots + verbs — same shape as `auth:*`. Both apps share the semver compare, release-parse, artifact pick, and once-per-boot rate limit in `packages/application/src/update.ts`; the `update` shell port carries `action: 'open' | 'install'` so the banner advertises exactly what will happen. Android sideloading is the distribution channel, so download+install intent is a real self-update there — `canRequestPackageInstalls()` routes the user to their own unknown-sources switch when unset, and the file URI never crosses into a browser context. No telemetry: the only egress is the check itself plus the artifact/download pages the user invokes. | If packaged builds gain electron-updater/Squirrel (signed, blockmap-capable artifacts), or a Play/other store channel ships, or the APK intent path proves unreliable on fielded devices, revisit the install level per platform here. |

## Presentation

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Waveform peaks extract client-side on desktop AND Android — a `PeaksPort` pulls the playing stream's own bytes and decodes them (WebAudio on web; `MediaExtractor`+`MediaCodec` in `modules/auqw-expo` on Android); iOS keeps the seeded pattern. The contract carries asymmetric pairs — `peaks?: {up, down}[]`, not `number[]` — and extraction/normalization share one implementation: raw per-window magnitudes (`PeakWindow`) reduced by `normalizePeakWindows` (5th–95th percentile → 0.05–1.0 → γ1.2) on the JS side for both platforms, so the native extractor stays a dumb decode+bucket. | Decided | Peaks are pure decoration — a provider-carried amplitude field would entangle every guest plugin's contract for pixels no behavior trusts. The open stream handle already owns the bytes, so the extraction is free bandwidth and zero wire surface; on Android non-demanding `streamPeek` positional reads feed an in-memory `MediaDataSource` — only already-committed bytes are served, a peek queues no demand, and a cancelled sweep leaves nothing competing with playback — while `provider:'local'` handles resolve to their file/content URI and decode straight off disk under the same `maxBytes` extraction cap (the resolved length checked up front, or the consumed-byte bound when it can't be resolved). Local decoded PCM spills to a cache file the bucketer memory-maps rather than a whole-buffer heap copy, so peak allocation stays bounded next to the player. Pairs carry the stereo L/R split (mono: positive/negative half-wave energies) so the bars read organic rather than mirrored. | If iOS gains a decoder-backed path (AVAssetReader in the module) or a provider ships peaks essentially free, revisit — the renderer contract accepts either source. |
| Desktop peaks derive from sampled ranged reads, not the whole file — `web-peaks.ts` probes the stream seam (`stream_probe`) with bounded windows (head 256 KiB → container carve → Cues from head or a 128 KiB tail probe → ~24 clustered samples at 4-wide concurrency), synthesizes init+cluster documents per sample, and merges decode windows into sparse buckets; `lf-*` local handles, non-webm containers, and small files (`≤ SAMPLED_MIN_TOTAL_BYTES`) fall back to the legacy pull+decode. `PeaksRequest.onCoarse` fires at most once mid-extraction with real measured data only — never fabricated — so the tracker can publish a coarse profile while refinement continues; `useWaveformPeaks` renders whatever `tracker.get` returns each update (coarse then final, no visual pop — refinement swaps the same resolution buckets). Success caches under content identity (`recordingId` — the `id` prefix before `|attemptId`), so an adopted warm stream or a retried attempt reuses the same entry; failures stay attempt-scoped. A device-local `peaks_cache` table (schema v11, recording_id PK, peaks_json, fetched_ms, LRU 256) persists profiles behind a `PeaksStore` port (`createPeaksCacheStore` on `SqliteDriver`) — repeat plays serve the profile inside one DB read | Decided | The whole-file pull was the latency wall — extraction could not start until every byte was committed, then paid a monolithic decode, so real bars landed seconds after 'playing'. Measured on the latency model: stored-profile serves at ~10 ms post-pull, warm-adopted sampled coarse lands ~0.5 s, cold-stream coarse ~1.1 s — sub-200 ms first-render is only reachable on the persisted path or when the head bytes the mint already committed cover the coarse window. The honest floor is documented in `harness/latency-measure.ts` (`peaksLatencyModel`): probes are WAN round-trips on the minted session; nothing about them is free. Attempt-keyed caching guaranteed every retry re-pulled; content keying + persistence makes the second play instant where the first paid network. `peaks_cache` is deliberately NOT a `PersistedState` section — device-local cache must not cross sync export. | If a cheaper first-play path appears (e.g. provider-side peaks, warm streams extracting during pre-click pump-fill), or the sampled profile proves visibly wrong on real content, revisit — the coarse-then-refined contract and the content-keyed cache survive any extractor swap. |
| UI typeface is Inter (400/500/700 via `@expo-google-fonts/inter` on mobile, `Inter → ui-sans-serif → system-ui` on web/desktop); JetBrains Mono dropped, along with the "type is monospaced" Omarchy rule | Decided | Monospace read terminal-like rather than music-player; owner directed a Mistral-style sans shell (2026-09). Inter ships through the same bundled-google-fonts mechanism that carried JetBrains Mono — dependency swap, not a new mechanism. | If Inter's metrics break dense metadata/duration columns, revisit with `fontVariant: ['tabular-nums']` or a numeric-only mono fallback. |
| Settings `theme` gains `'adaptive'` — the `ThemeSourcePort` contract is `{scheme, palette?}` pushed over `theme:events`/`theme:subscribe`; `chrome:scheme` widens to `{scheme, canvas?, symbol?}`; SQLite `settings` rebuilds (schema v8) to admit the value | Decided | Scheme sources shipped per design.md: Electron main owns file watchers (Omarchy colors.toml, KDE kdeglobals) and the GNOME portal accent poll, refcounted on renderer subscription so platforms only pay while `adaptive` is selected; Android reads `system_accent*`/`system_neutral*` stops via auqw-expo, iOS stays flag-only. Palette polarity follows `bg` rather than the OS flag — the palette is the source of truth. | If a source emits a palette that should follow the OS flag instead of its own bg luminance, revisit the polarity rule; win32/darwin `systemPreferences` accent path is written but unverified on real hardware. |
| `react` joins `@auqw/ui-shared` as a peer dependency (`*`) — `shell.ts` hosts the shells' shared hooks (`useSerializedWrite`, `useOverlayStack`, `useSmoothedPosition`) | Decided | The hooks were duplicated verbatim across both app shells; hoisting them is the point of the package. The pure cores (`createSerializedWrite`, `overlayReducer`) stay dependency-free for node-side tests. | If a non-React consumer needs the pure cores and tree-shaking can't keep `react` out of its graph, split `shell.ts` into a react-free module and a hooks module. |
| `react` joins `ui-shared` as a peer dependency for the new `controllers` subpath — headless per-screen hooks that own the duplicated view-model derivations screens copy-pasted between ui-web and ui-native | Decided | The dedup target lives above the view-model mappers: row models + bound callbacks + screen-local `useState` (filter/sort/layout, stage mode, gallery controls) are React-shaped, so the shared layer needs the runtime. | The refresh grant is the only persisted auth credential — one sealed record `auqw.auth.session` `{v:1, refreshToken, clientId, grantClientId, pendingFlow?}` under Electron `safeStorage` (desktop, dedicated `auth-secure` dir reachable only via the `auth:custody` service channel) and `expo-secure-store` (mobile, Keystore/Keychain); access tokens live in memory + the host's auth slot only | Decided | A refresh grant is a long-lived credential — plain prefs would leak it to backups/renderer code. The sealed record mirrors `sync:keys` custody exactly; the client-id override (a preference, not a credential) rides the same record so writes stay atomic and sign-out can drop the grant while preserving the user's override. `grantClientId` binds the grant to the client_id that ISSUED it — renewals ride the issuer's credentials forever, and a mid-flow override edit can never re-bind an existing grant to credentials it wasn't minted under. `pendingFlow` persists an in-flight device flow (code + expiry + issuing client): it is written before the code is offered, dismissal does not cancel the poll, and a process killed mid-approval re-arms the same poll on restore — a granted verdict can never be discarded by interruption; terminal verdicts and every whole-record write preserve-or-clear it consistently. A device grant that arrives without `refresh_token` fails sign-in rather than half-linking. | If custody must hold per-account rows (multi-account) or the store proves unreliable on a target OS, widen the record versioned (`v:2`) here first. |
| Access-token refresh is a simple armed timer at expiry − 60 s (min 5 s out) with bounded retry backoff (30 s → 10 min); a revoked grant (`invalid_grant`/`unauthorized_client`) drops custody + the host slot exactly once. `AuthSnapshot.bearerLive` reports whether a live access token actually sits in the host slot — `signed-in && !bearerLive` means linked-but-dead, so recovery CTAs keep showing while a renew is still failing | Decided | Google access tokens carry an honest `expires_in` (~3600 s) — a timer is simpler and more predictable than lazy refresh keyed on host feedback, and prepared sessions re-read the slot at re-mint so an in-flight recovery picks the healed token. Bounded backoff covers offline sleeps; a dead grant must not retry forever nor strand a live bearer. | If hosts signal near-expiry themselves or tokens arrive with pathological lifetimes, revisit the margin/backoff; the `AuthClock` seam keeps the policy injectable. |
| On desktop the OAuth client runs in the utility process, never the renderer — `auth:*` IPC channels expose status/verbs only, `auth:openUrl` allowlists `*.google.com`, and `auth:state` pushes validate before relaying | Decided | The renderer CSP admits no remote `connect-src`, and token material must never cross into a sandboxed webContents — status snapshots (device pair + state) are all the UI needs. Folding application error kinds onto the shell envelope keeps the boundary's vocabulary closed. | If a second auth-bearing surface lands (e.g. an in-app browser), widen the port rather than opening a generic URL channel. |
