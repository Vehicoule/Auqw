# Decisions

Statuses: **Decided**, **Deferred**, **Open**. Each row carries its
rationale and the condition that would reopen it.

## Capability surface

| Decision | Status | Rationale | Reopen when |

| `catalog.suggest` joins the ABI — keystroke query completions (`{input, limit?}` → `{suggestions: string[]}`) | Decided | Typing fetched full catalog pages per keystroke — heavyweight, slow, and the ranking varied per catalog provider. Completions are one small response, provider-independent, and typo-corrected upstream (predecessor app's `get_search_suggestions` model). | If completions prove consistently worse than live results, revisit; commit path unchanged. |
| `catalog.suggest` has no settings slot — it routes automatically over declaring providers | Decided | Suggestions are provider-independent by design: whichever loaded provider declares the capability serves the draft pane (first declarer, registration order). A per-slot choice would fragment the typing surface without benefit. | If a second declarer lands and ordering matters, introduce routing policy in this log first. |
| Typing no longer runs `catalog.search` — results commit on Enter or a suggestion tap | Decided | Removes per-keystroke catalog load; the committed query is also what caches and recents record, matching what the operator actually searched for. | If users need live results while typing, gate behind a setting — default stays suggestions-first. |
| Playlist-wide download (`onDownloadAll`) reaches desktop — the entity screen's download control requests only MISSING entries | Decided | Mobile already shipped the affordance; desktop had the same `DownloadManager.request` path and the same partial-state ambiguity (a playlist read 'partial' forever when held bytes couldn't be told apart from unplayable rows). Requests filter by byte-ownership (`downloads.fileFor` / local `uriMap`), never the playback-capability probe — `localPlaybackFor` answers 'can the player attach these bytes', not 'does the ledger hold them', and probing it would re-request stored tracks and delete their files on a changed mapping. | If request scope should widen (e.g. re-fetch on a changed mapping), decide the ledger's replace semantics here first. |
| `stream:read` stays a parked demand read; decorative consumers use `stream_peek` — a serve-only positional read (`bytes` = committed hit, `[]` = confirmed EOF, `None` = unfetched hole) that queues no fetch-through and never parks | Decided | A parked `stream:read` outlives any caller-side timeout, and its queued demand outranks the player's own (demand serves min position first) — a decoration can stall playback. Rather than retract demand with a per-read cancel (`requestId` + session cancel = real contract work), the peek has no demand to retract: abandonment is local — the poll loop just stops polling. Android binds it as `streamPeek` for waveform peaks; `provider:'local'` handles never reach the seam — they decode straight off the file/content URI. The desktop port keeps its deadline-abandon until it adopts the same seam call. | If a decorative consumer needs pull-through (a hole it must fill rather than abandon), or the desktop port shows the same demand reordering measurably, revisit — request-scoped cancel on `stream:read` is the fallback shape. |
| `stream_probe` joins the stream seam (registry `probe`, host-surface `stream_probe`/`stream_probe_blocking`, napi `streamProbe` on the inner runtime, uniffi `stream_probe`, desktop `stream:probe` → `StreamProbeResult{data,total,eof}`): a peek-first bounded positional read — a committed hit serves like `stream_peek`; on a hole + `fetch:true` it drives ONE ranged GET through the session's own `Fetch` (the minted URL/headers path) sized `min(max_len, chunk_bytes)` and commits the bytes into the sparse store so playback serves them free; pump cooldown/429 maps `RateLimited`, 403 `Expired`, 416/`!EOF` `eof:true`; `fetch:false` degrades to exactly a peek. The IPC boundary caps `maxLen ≤ 1 MiB` | Decided | The waveform's sampled extraction needs bytes at arbitrary offsets a demand read would serialize behind the player's own queue (demand serves min position first) and a peek cannot produce at all. The probe bypasses the demand queue but reuses the minted identity, so each probe is one WAN round-trip that doubles as speculative fill — every probed range lands in the store `stream:read` would eventually have fetched. It stays bounded and cancellation-free like the peek: a probe job abandons between calls, there is no mid-fetch retract contract. | If probes prove to need mid-fetch cancel, or probe-driven fills measurably starve the player's own demand, revisit — a demand-priority split or request-scoped cancel is the alternative shape. |
| Desktop download fetches ride `transfer:fetch*` utility channels — `transfer:fetch` answers `{status, headers}` for a GET, `transfer:fetchBody` streams the body once (8 MiB cap, base64), `transfer:fetchAbort` cancels a parked request idempotently; Node `fetch` beside the transfer sinks, ≤3 manual redirect hops re-validated https-only with the caller's headers verbatim, literal private/loopback targets refused on every hop, a 120 s backstop reporting `transient` | Decided | The renderer's CSP (`connect-src 'self' http://127.0.0.1:*`) forbids https outright and Chromium drops the forbidden `User-Agent` — a minted download URL was unfetchable from the renderer by construction, so downloads failed before the first byte. The utility already owns the files those bytes land in; fetching beside the sinks keeps the wire leg inside the trust boundary and sends minted headers verbatim, while the private-host refusal keeps the bridge from reaching past the renderer's own CSP boundary toward loopback/LAN services. A head/body pair is single-use and abort-addressable — a cancelled download can't double-read a stream or leak a socket. | If the renderer's connect-src ever needs https for another reason (the pump boundary argues it shouldn't), or a download needs a streamed body above the cap, revisit the channel shape here first. |
| The manifest destination allowlist covers `artworkRef.url` alongside the top-level `done.result.url` | Decided | The allowlist validated only `done.result.url` at `crates/plugin-host/src/invoke.rs:454`; the nested `artworkRef.url` crosses to the renderer unchecked, so a guest reaches an https destination the manifest never declared from a process otherwise restricted to its `network:` permissions. On desktop the renderer's `img-src 'self' https:` hole (Presentation) makes that fetch succeed. | If artwork ever becomes a first-class signed capability with its own origin grant, fold it into that row rather than extending this list. |
| A bare `416` maps to `eof:true`; the registry's `Content-Range: bytes */N` check stands | Decided | `crates/auqw-stream/src/registry.rs:475-485` returned `eof:false` on a bare 416, so an end-of-stream probe burned an extra round trip or dropped into the slow whole-file fallback exactly at the end. No playback correctness loss — the pump path is unaffected — but the code and the row disagreed, and the row is the artifact a future reader trusts. | If a bare 416 is ever observed to mean "range not satisfiable for a live resource" rather than "past the end", amend this row rather than the code. |
| Embedded cover art extracts beside the tags into a platform content-addressed art store — `LocalTags.artworkUri` joins the seam: the reader persists the ORIGINAL picture bytes under `filesDir/art/` (Android `embeddedPicture` → `Uri.fromFile`, magic-byte ext) / `$AUQW_USER_DATA/art/` (desktop `common.picture`, mime ext) named `<sha256>.<ext>`, answering a `file://` ref (null on no picture / write failure — never a per-doc error). The engine mints `recording.artwork` as `{url, width:null, height:null}` for local recordings and fills EMPTY art slots on provider joins (catalog art never clobbered; `isArtworkUrl` admits `file:///`), and a one-pass backfill re-reads tags on unchanged files whose recording carries no art — an in-memory `#artChecked` set marks honest-nones per boot so artless files aren't re-read every scan (marks land post-commit; a failed commit retries). `file://` refs are device-local minted-only: provider payloads and the sync wire take `isRemoteArtworkRef`/`isRemoteArtworkList` (https only), and `portableArtwork` strips them at export + sync emission and on import accept — a receiving device re-derives cover art from its own backing file. Since the import wipes `local_files` while `local_sources` grants survive, a rescan of the retained sources is what rejoins rows and re-extracts covers without a manual scan — and the need is DERIVED, not caller-flagged: any rehydrate that rebuilds onto live grants over an empty file index arms the rescan on the surviving instance (a mid-flight retire cancels the in-flight scan through the linked lifecycle signal, so only the replacement can carry it — a concurrent applied-sync rehydrate otherwise starves the merge permanently), and a transient `storage.load` failure retries once on a signal linked to the caller's so a cancel still releases the rehydrate tail. A superseded `LocalFileSource` can still have that scan in flight when a second import lands — its commits go straight to storage, so instance replacement calls `retire()`: an instance-wide lifecycle signal links every op's caller signal (in-flight enumerations/tag reads/commits cancel) and the returned drain promise covers the write tail plus the scan set; `replaceLibrary` awaits it before `importLibrary` so a stale commit can never resurrect rows the previous swap wiped, and rebuild/dispose paths retire-and-forget | Decided | Local files rendered the note-glyph placeholder — no cover, no art bleed, the empty stage. The bytes sit beside the tags already read (APIC frame / `embeddedPicture`), so extraction rides the same batched retriever open. Content-addressing makes identical covers land once and turns re-scans into write-skips; original bytes go down un-resized — no image-codec dep on either host, `<img>`/`Image` downscale GPU-side, and `file://` skips the https-only artwork LRU by construction (desktop CSP reads `file:` as `'self'`). `filesDir`/user-data over cacheDir: unchanged docs never re-read tags, so an OS-reaped file would strand artwork permanently — the store's lifecycle must match the recordings table's. The backfill is a memory pass because a `local_files` schema bump would persist exactly what the per-boot set already bounds; a negative mark only pays one retriever open per artless file per boot. The boundary split mirrors the artworkRef allowlist logic: a `file://` ref from a guest or wire payload could point the renderer at arbitrary local files, and a device-local path is meaningless on another device. | If art needs bounded storage (a size budget + LRU instead of lifecycle-parity), covers should be re-encoded/resized at store time (needs a codec dependency in each host), `width`/`height` should be filled from the picture (decode for dims), or exported art should transport the BYTES rather than re-deriving at the destination, record the new store/boundary contract here first. |

| `catalog.search` grows typed discovery: the payload gains optional `kinds` (subset of `track|album|artist|playlist`; absent = all kinds) and `continuation`; the result gains optional `entities` (`entityMetadata[]`), `top_hit` (`{type:'track',item}|{type:'entity',item}`), and `continuation` (null = no next page) | Decided | Track-only results forced a single catalog axis: providers already serve artist/album/playlist hits the host dropped at decode (`toTrackItems` skips well-formed non-track rows), and entity pages were unreachable from search. `kinds` keeps a chip re-query honest — a scoped filter fetches the right endpoint at a real limit instead of slicing the mixed page. `top_hit` is a tagged union because `source_ref.kind:'album'` is ambiguous between a track row and an entity row (deezer emits both), so the tag discriminates. Undeclared fields are simply unemitted — a provider opts in per field, no capability split. | If `entities` ever needs a cross-kind interleaved rank beyond provider order within per-kind sections, or a third hit type appears, revisit the tagged-union shape here first. |
| `catalogEntityResult` gains optional `related` (`entityMetadata[]`); `entityMetadata` gains optional `group` (`'discography'|'related'|'featured'|'appears-on'`) | Decided | An artist page is tracks + albums + similar artists upstream, but `items` carries only `trackMetadata` — deezer emitted its album list inside `items`, where the host dropped it as well-formed non-track rows, so artist pages lost their discography. `related` gives entity pages real sections in provider order; `group` tags which upstream shelf an entry came from so hosts render localized section titles without per-provider shape knowledge. | If providers need more than the four section kinds (e.g. singles-vs-albums splits, members, episodes), widen the enum here first. |
| `'playlist'` joins the entity taxonomy end-to-end — `sourceRef`/`entityRef`/`entityMetadata` kind enums, `EntityKind`, `LikeEntityKind`, and storage v15 rebuilding the `entities.kind`/`likes.entity_kind` CHECKs | Decided | Provider-curated playlists and mixes (editorial, themed, artist-based) are a first-class catalog page: own id, artwork, curator subtitle, and a track listing like an album's but distinct provenance. Reusing the entity pipeline — live page fetch, like target, library card, queue origin — avoids a parallel type; `likes.entity_kind='playlist'` targets `entities` exactly like album/artist. Sync compatibility: older peers' persisted-document validation skips playlist-kind records per record (never batch-fatal), so a liked playlist degrades to absent on pre-v15 peers rather than breaking the merge. | If playlist entities need library semantics beyond like (e.g. subscribe-to-changes), or pre-v15 peers must preserve rather than skip the records, reopen. |
| Search/discovery renders typed: `entities` become per-kind card rails in `artist→album→playlist` order sharing the `EntityCard`/`EntityRail` views (card opens the entity page, heart likes it); the tagged `top_hit` drives the hero variant (track = play hero, entity = open hero); `SearchFilter` grows `artists|albums|playlists` chips that re-query with `kinds` ('library' narrows a committed unscoped page locally); `entity.rail.<group>` localized titles label an entity page's `related` shelves | Decided | One card/rail view-pair across search sections and entity shelves keeps surfaces convergent — the rail card is the provider-agnostic unit a playlist/artist/album shares. Scoped chips must carry a real limit from the provider, so they re-query with `kinds` rather than slice the mixed page; 'library' is the exception — membership is host-local data, so it filters the committed page without a refetch. | If a surface needs interleaved entities or see-all pages per rail, revisit here; if group titles need provider-supplied strings, widen `related` entries rather than special-casing locales. |
| Result paging rides `continuation`: `SearchSession.searchMore` appends through `mergeSearchPage` (ref-dedupe, base top-hit stands, fresh token wins) and an append never publishes 'loading' — the base page stays up with a row-level busy affordance; a failed append re-publishes the base with `refreshError`, never the error screen | Decided | Deezer caps a search page ~25 rows upstream, so discovery quality needed a second page; treating an append as a new search would flash a skeleton and could drop delivered content on a transient failure. The continuation key enters the cache key so a next page never collides with the page it continues. | If providers return cursors that invalidate earlier pages (live feeds), revisit append-vs-replace here. |
| `catalog.browse` stays out of the contract for now — a charts/genres/editorial home surface is its own slice, not a search capability | Deferred | Provider home feeds diverge in kind (deezer `/chart` returns one flat top-N per entity kind; YTM `browse` home is a nested shelf tree incl. mood/genre chips and community rows; iTunes RSS feeds are storefront-scoped hit lists) — the only honest common shape is `sections: [{title?, items, entities}]` with optional `continuation`, i.e. `catalog.entity`'s related-shelf shape minus the entity header. Declaring the capability now would freeze a contract no slice exercises: search/entity/suggest cover the approved discovery scope end-to-end, and an unexercised `catalog.browse` is a dead schema — nothing serves it, nothing renders it. When scheduled, the implementation is cheap: reuse `entityMetadata`/`trackMetadata` per section, route through `catalogProvider` like `catalog.search`, render sections through the same `EntityRail` view-pair. | If a home/discovery surface is scheduled in a slice, or a provider ships a feed the search pipeline cannot express (e.g. genre chips, editorial picks without a query), implement per the sketch here — the deferral is about freeze-order, not value. |

## Plugin guests

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Plugin artifacts ship OTA, never bundled: the app embeds only the ed25519 public key + feed URL and fetches signed releases from `releases/feed.json` on Auqw-plugins main at runtime (first open and periodic check), verifying each artifact's signature + digests against the embedded key before caching under the app's plugin dir; `providers.lock.json`, `tooling/sync-plugins.mjs` staging, the `plugin-lock` CI gate, and the Metro/desktop asset bundling are all deleted | Decided | The build-time pin flow made every plugin change a two-repo, order-dependent chore (sign in plugins → repin the lock → plugin-lock CI reads a sibling checkout of plugins main — repins couldn't green before the release merged, and parallel sessions collided on the same version). Prerelease with no installed base makes bundling pure cost: the trust root reduces to one public key, the artifacts already carry signature + provenance, and plugin releases now ship without touching the app repo at all. ABI collapses to a single `0.1.0` (all capabilities) — the 0.1/0.2/0.3 tier matrix only existed to serve an installed base that doesn't exist. | If the app ever ships to a real installed base, bundle a fallback plugin set again (offline first-boot) and reintroduce per-version ABI tiers with the next contract break; if feeds move off the plugins repo's raw URLs, the embedded feed URL follows the same row. |
| `serde` (derive) joins youtube-music guest deps for `radio.seed`'s `next` parse | Decided | A 565 KB `next` body as a `Value` DOM burns ~340 M fuel against the 200 M per-entry cap — the mobile `budget-exceeded: fuel` failure. Typed structs with per-field tolerance visitors parse once (~84 M fuel) at identical skip semantics. serde + serde_json were already SDK deps; this adds only `serde`'s `derive` feature to the guest crate. | If the guest grows a second large-body endpoint, generalize the opt_* helpers into the SDK or revisit a streaming parse. |
| `headers` joins the `playback.resolve` result (optional object, ≤16 entries, RFC 9110 names, values ≤512): the mint's required fetch headers ride `PreparedSource` → `core.source` → every `Fetch::get_range` verbatim incl. the one redirect hop and each re-mint, and — for downloads — `PlayableResource.headers` → `runTransfer`'s chunk fetch verbatim incl. each re-mint (desktop over `transfer:fetch*`, mobile direct); host-owned names (`range`, `host`, `content-length`, `connection`, `transfer-encoding`, `accept-encoding`, `te`, `trailer`, `upgrade`, `expect`, `keep-alive`, `proxy-*`, `www-authenticate`, `authorization`, `cookie`, `set-cookie`) are rejected `invalid-response`; `ReqwestFetch` falls back to `auqw/<ver>` UA when the mint names none | Decided | The pump previously fetched signed URLs with no request headers at all — an empty-UA GET that providers score as bot traffic, so rungs whose minted URL is client-identity-bound were refused after a successful resolve. Downloads broke twice over this same field: the TS wire decoder's strict key check rejected the then-undeclared key outright (`invalid-response` on every resolve that carried it), and once decodable only the pump path consumed it — the download fetch still sent empty-UA. A plugin-minted URL must carry its fetch identity (the minting client's `User-Agent`) — the host can't guess it from `client` without importing rung internals. Host-owned names stay host-owned at the boundary, mirroring the predecessor's forbidden-source-headers gate; the UA fallback keeps a fetch from ever going out identity-less for header-less mints. | If a second provider needs fetch headers beyond `User-Agent` (e.g. `Origin`, `X-Goog-*`), the field already carries them; if a guest wants per-request header state rather than mint-time, that is a `host_request`-level decision, not this row. |
| `provider-wall` joins the guest-visible error taxonomy (ABI contract, `GUEST_FAIL_KINDS`, the app `ErrorKind`, and a `StreamError::ProviderWall` seam variant) for a provider-side refusal of the session's visitor/IP — the verdict a bot-check wall reports | Decided | The wall previously smuggled through `transient` + a `bot-check` message sniff on the last `:`-segment — a string protocol hostage to every prefix-wrap between the guest and the toast. As a kind it survives the wire verbatim (`fail.error.kind` is a declared field end to end), lands `retryable:false` for free, and `isBotCheckWall` recognizes it without sniffing (the sniff stays for pre-0.4.6 guests). It is terminal, not row-condemning: neither `RETRYABLE` nor `PERMANENT_FAILURE_KINDS`, and the stream pump's transient-retry leg deliberately does not match it (a re-mint asks the same wall). The seam maps it to HTTP 502 alongside the other upstream verdicts. | If a second wall-flavored verdict needs distinguishing (e.g. region-gate vs bot-check), split the kind here; if a guest needs richer wall detail (provider, wall type), that's a `fail` payload field decision, not another kind. |
| The `manifest_digest` pin that used to live in `providers.lock.json` now lives in `releases/feed.json` — each feed entry carries the signed manifest sha256, and a new release dir + feed entry only ships through a reviewed PR on Auqw-plugins (the manifest's `network:` grant is reviewed as part of the manifest source, which the signature then authenticates) | Decided | Same rationale as the original pin: the canonical signature authenticates whatever manifest sits next to it, so the reviewed grant must be part of what ships. Deleting the lock removed the pin point but not the concern — the feed carries the digest instead. | If manifest grants are instead moved to a separate, independently signed authorization file, define that file's key and rotation here first. |
| The lyrics waterfall's tier count is bounded by the host's invocation deadline, with tiers skipped (not failed) once the remaining budget cannot cover them | Decided | Ten sequential tiers are not reconciled with the host's 30 s invocation deadline, so the honest "no lyrics found for this track" answer degrades into a budget-exhaustion error — a different user-facing state, and under the project's own evidence rules a different class of result. | If the host deadline is raised, revisit the tier count here rather than letting the two drift apart again. |

## Playback

| Decision | Status | Rationale | Reopen when |
| --- | --- | --- | --- |
| Shuffle deals a play order, not a queue order: `QueueProjection.order` carries a permutation of item indices the cursor walks — dealt at toggle-on as the canonical prefix through the cursor + successors shuffled uniformly within their block (manual picks first, radio-tail suggestions after) | Decided | Canonical `items` (and the persisted queue) stay untouched, `previous` keeps real history, and the strict immediate-successor legality check on `queue-transition` survives — a random-next rule would have to accept any target. Mirrors ExoPlayer's ShuffleOrder model. The dealt walk keeps the canonical user/suggestion boundary — a suggestion never plays ahead of a manual pick — so the rendered queue sections (now playing → up next → autoplay → history) stay the true play order. Mutations reconcile the deal: removed occurrences drop out, new ones insert at uniform random positions inside their own block behind the cursor's dealt position, an interleaved upcoming run repartitions on read, and dealt successors never reshuffle. `repeat=one` still replays the cursor item; `repeat=all` wraps the dealt ends (tail→head on next/ended, head→tail on previous); a lone item self-wraps into a restart. | If a random-next mode (suggestions may interleave) is requested, revisit here first. |
| `provider:'local'` on desktop attaches `file://` URIs directly on the audio element — the renderer mints `lf-*` handles keyed to the URI (the mobile adapter's `lf-*` convention: no seam, no new protocol, no pump lease); `localPlaybackFor` answers the real `createLocalPlayback` probe | Decided | The session already routed owned URIs to `provider:'local'` prepares — only the attach leg was missing. A `file://` element source is the simplest route that plays: Chromium decodes and seeks the file with native random access, so no ranged IPC, custom scheme, or utility round-trip is needed. `media-src` admits `file:` next to `'self'`; ownership vs attachability stays split (`fileFor`/`uriMap` for ownership, the probe for attach). The reported mime derives from the shared extension table (`shared/audio-mime.ts`, hoisted from the utility's tag map), then the download ledger's recorded mime for extensionless `dl-*` names, then `audio/*`. | If a container Chromium can't decode must play (`.ape`/`.dsf`/`.wv` are admitted by the scanner's table but not Chromium), or a platform webSecurity rule blocks `file://` element loads, revisit — the fallback shape is a `stream:*`-shaped file pump feeding the existing loopback/MSE attach. |
| A `file://` URI mints an `lf-*` handle only through `local:resolve` — the utility's realpath + grant-confinement gate (`allowedLocalPath`: realpath'd path must sit under the media dir or a `local_sources` tree root, picked-file roots matching exactly); a null answer fails the prepare `unavailable`. Byte consumers that can't use the element (waveform peaks on `lf-*` handles) ride `local:read` — the same gate, positional ranged read, base64 out, empty at EOF | Decided | The renderer's lexical `file://` string can't realpath (no fs), and confining at index time leaves the TOCTOU gap a post-scan symlink swap exploits — the check has to run at attach time, in the process that owns the filesystem. `local:resolve` answers the re-keyed (realpath'd) URI so the element attaches exactly the path the gate approved; `local:read` exists because Chromium `fetch()` cannot read `file://` and `lf-*` handles carry no seam session for `stream:read`. Both are args-guarded like every `local:*` channel (bounded URI, `maxLen ≤ 1 MiB`). | If peaks adopt the mobile `stream_peek` semantics for local files too (cache-file spill, memory-map bucketing), or confinement gains a third root kind (e.g. session-picked single plays), extend the gate here. |
| Handle-keyed stream ops (`stream:serve-url|open|read|close|release|marks`) report a dead registry session as `released`; session re-prepares on dead-handle kinds from transport calls AND async `failed` statuses (the element's probe path), while a dead-handle pause reports ok | Decided | Serve-url sessions detach on pause (the last range conn ends) and the reaper evicts them past the 120 s TTL, so a long pause outlives the stream. `not-found` there is dead-resource semantics, not malformed input: mapping it to `released` lets session re-prepare from the queue's persisted position instead of `markUnplayable` + 0:00 reset. DOM-only ops (seekTo/pause on the web player) never touch IPC, so the dead URL surfaces as an async media error — the player probes handle liveness (`stream:marks`) before labeling it transient. | If a handle-keyed op gains a not-found source that is genuinely caller error (e.g. bad arg shape), split that slug back out. |
| Playback resolve+prepare warms ahead of the tap: `PlayerPort.prewarm(provider, sourceRef)` mints one advisory, unattached registry session a same-key `prepare` adopts (registry `adopt_reusable` + host-side fast path that skips the guest invoke); rows the user can reach warm their mappings through a serial candidates pass — up to 9 surface-handed ids or `TrackMetadata` rows per `session.prewarm()` plus the dealt window behind the cursor while playing, deduped by a 64-entry seen-LRU; a track row whose catalog provider differs from playback candidates-resolves into the stream warm's `(provider, ref)` key directly — no mapping or pin commits, since no recording exists to land them; a fresh surface row (hand or resolved backlog) outranks the dealt successor under playing — the visible page is the likelier tap — and each `prewarm({tracks})` hand replaces the visible key set, so a match resolved for a page that left view is discarded and unseen rather than minting over what is on screen; newer hand kinds extend the same space — `prewarm({occurrenceIds})` names a set of queue rows (an already-resolved row mints straight from its stored `selectedRef`, an unresolved row resolves then mints as an `o:`-keyed surface entry evicted when its occurrence leaves the queue — the on-screen up-next page uses it, refined live by the list's viewability reports as the viewport moves), `prewarm({focus})` is one newest-wins slot the row-intent debounce feeds for hover/focus/touch-down gestures ({occurrence | recording | track}; a recording focus may carry the row's own pin — playlist entries pass their `selectedRef` resolved through the same preference rule as play, so the warm lands on the ref the tap would pick; a focused occurrence's pending resolve keys `f:o`-namespaced so the next focus hand kills it and a stale result never displaces the row under the finger), and `enqueueRecording` re-hands each committed row's occurrence id so a just-enqueued tap adopts instead of resolving cold; the stream warm's queue-side want covers every settled stretch (buffering/playing/paused) with the row `next()` would land on — first unmarked dealt successor, head-wrapped under `repeat=all` — plus the parked cursor row itself while a paused queue sits idle (a cursor moved while paused, a restored session), since its resume press is that row's attempt; warms minted into dead time (URL inside the attach margin, flagged or removed row, queue-mode flip) are cancelled/released at want-re-eval or adoption, never sat out on the 120 s TTL | Decided | TTFS: the tap's resolve+mint latency is already spent when the finger lands (the predecessor's visible-streams LRU model), without the media element, operation generations, or attach lifecycle being touched. Folding application error kinds onto the shell envelope keeps the boundary's vocabulary closed. | If a second auth-bearing surface lands (e.g. an in-app browser), widen the port rather than opening a generic URL channel. |
