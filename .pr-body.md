## Summary

Sync moved bytes but libraries never converged, in both directions: `applyDelta` merged remote entries into the change log with nothing materializing into the domain db, and no Session write path called `localChange`/`localChangeBatch` so local edits never entered the log. This leg closes both directions on desktop AND mobile: a shared pure projector (`sync-projection.ts`), a `SessionDeps.sync` emit seam, and `Session.applySyncedEntries` — plus a bounded applied-outbox over IPC on desktop and an `onApplied` engine wrap on mobile.

**Emission** — `LocalWrite[]` builders per `SyncRecordKind`, called AFTER each successful syncable commit, best-effort (typed warn + `persistenceError` surface, never a rollback):

| Kind | Fields | Record id | Domain section |
|---|---|---|---|
| `recording` | title, artist, album, durationMs, releaseYear, artwork, explicit, genre, isrc, versionLabels, provenance | `recordingId` | `recordings` |
| `recordingSourceRef` | ref (presence) | `sourceRefRecordId` | `recordings[].sourceRefs` |
| `recordingMapping` | status, score, evidence | `mappingRecordId` | `recordings[].mappings` |
| `like` | like (presence) | `likeRecordId` | `likes` |
| `entity` | kind, title, artistName, artwork, createdMs | `entityId` | `entities` |
| `entitySourceRef` | ref (presence) | `entitySourceRefRecordId` | `entitySourceRefs` |
| `playlist` | name, createdMs, updatedMs | `playlistId` | `playlists` |
| `playlistEntry` | playlistId, recordingId, position, selectedRef, addedMs | `entryId` | `playlistEntries` |
| `playEvent` | event | `eventId` | `playHistory` |
| `playCount` | count, lastMs | `recordingId` | `playCounts` |
| `matchReview` | recordingId, createdMs, status, resolution, resolvedMs, candidates | `reviewId` | `matchReviews` |
| `settings` | theme, storefront, providers, qualityKbps, prefetch (changed only) | `SETTINGS_RECORD_ID` | `settings` |

Recording delete emits its tombstone plus tombstones for every dependent sync record; inbound the projector drops the row + dependents, matching the storage cascade.

**Projection** — `projectAppliedEntries(outcomes, current) → {batch: StorageBatch, changedKinds}`: folds applied `MergeOutcome`s onto current sections (section arrays only; the Session commits through its normal path so FK ordering matches `importOwned`). Partial remote inserts materialize with domain defaults or hold as `pending` until a valid row exists — never a malformed row. `decodeRecordId` decoder lives next to the encoders.

## Design choices

- `applySyncedEntries` runs inside the storage segment (same serialization as `#reviewOp`), unions retained `syncPending` + the page (fresh data never truncated — `SYNC_APPLY_PENDING_MAX` bounds only the post-failure backlog), projects → commits → mirrors → publishes; commit/load failure retains the union + `persistenceError` (cleared on success), non-applied outcomes drop with a warn (`superseded` never auto-restores — divergence history + `restoreLoser` own that). Remote settings rows reconcile against the providers the build actually has before commit. Returns `SyncApplyReport.rehydrateMedia` when the batch touched `downloads`/`localFiles`.
- Emit drains FIFO in `SYNC_EMIT_CHUNK` slices; a failed emit keeps the chunk for the next drain and `SYNC_EMIT_PENDING_MAX` bounds only that retained backlog — a healthy emission ships whole however large the commit.
- Desktop: renderer `sync` dep → preload `auqw.sync.localChanges`. Utility keeps a bounded outbox (4_096 volatile outcomes + JSONL spill at `${userData}/sync-applied.jsonl`, same durability horizon as the sync log) fed by every socket `applyDelta` and clipboard `sync:importDelta`. **Spill mode is write-through + peek/ack**: each outcome appends to disk BEFORE `applyDelta` acks; `sync:drainApplied` streams a byte-budgeted peek through `spillScan` (incremental line walk — never a whole-file read), and `sync:ackApplied` advances a `.off` sidecar byte offset instead of rewriting the file — `compactSpill` (stream → tmp → rename → reset offset) runs only once the dead prefix dominates (`>= max(1 MiB, size/2)`), so each byte is rewritten O(1) and a stale offset self-heals (`off > size` → rescan from 0). `sync:materialized` pages `engine.materialize()` for the rebuild path — one snapshot per pass (`materializedSnapshot` per offset-0 chain) so pages can't observe a live merge mid-walk. The renderer's drain is mutex-serialized (`draining`/`drainAgain`) so concurrent drains can't ack-overlap the same file prefix.
- Mobile: `createExpoSync` wraps `engine.applyDelta` once with `onApplied` so every inbound merge (syncNow pages + direct callers) notifies — `SyncRoundOutcome` doesn't carry `ApplyResult`, so the engine seam is the minimal honest one. Session `sync` dep = `createSyncEmit` (session/sync-emit.ts): a serialized tail + pre-surface buffer that flushes the moment the surface lands (web/fake builds stay unbound). `applyMaterializedEntries(engine.materialize())` runs once at sync bring-up — pending is memory-only, the durable log is the recovery net. `expo-secure-store` now lazy-loads — Metro-only module, unresolvable under node ESM; production behavior identical.
- **Emit durability beyond the session**: `#emitSync`'s queue is memory-only, so two nets catch committed writes a past life stranded. (a) `dispose()` runs one final `#drainSyncEmit` AFTER `#drainAll` — the cancel loop kills the in-flight drain mid-send, and a graceful quit gives the retained chunk a fresh uncancelled source. (b) `Session.emitUnsynced(synced)` / `unsyncedWrites` — a boot-time existence diff of domain rows against the engine's materialized `(kind, recordId)` set: every write whose record is absent re-emits (upserts only — never tombstones, which would resurrect-and-delete). Desktop's boot reconcile collects the id set while paging (ids only — no full-view retention) and diffs once the pass completes; mobile diffs from `engine.materialize()` at bring-up. Existence-level by design — a stale field on an existing record is merge business, not durability.
- **Applied outcomes carry `record: MaterializedRecord`** — the post-merge surviving field snapshot the projector hydrates folds from (`absolute` flag). A losing tombstone can no longer delete a row the engine still materializes, sum fields apply absolute (not delta), and every replay is idempotent — the property peek/ack relies on.
- **`'sum'` writes assert the aggregate**: `localChange`/`localChangeBatch` translate the asserted domain total into this device's component (`target − remote share`, clamped ≥ 0) inside `writeChanges` — the only place that sees per-device splits. Emission stays honest (emit the domain row verbatim) and projection never derives a component from an aggregate.
- **Materialized recovery**: `projectMaterialized` folds `engine.materialize()` records through the same section logic; `applyMaterializedEntries` shares `applySyncedEntries`' commit tail (`#commitSyncProjection`). Records absent from the set keep their rows — "never synced", not deleted. Unmaterializable records ride `pendingRecords` → bounded `materializedPending` → unioned into the next call, so desktop applies each byte-bounded page as it arrives (staged, memory-bounded) while dependents still resolve across page boundaries. Desktop triggers the reconcile after the boot drain AND whenever a drain reports `dropped`; mobile once at bring-up. This is the durable-projection-cursor alternative the reviewer offered, implemented as a rebuild from the durable log.

## Decisions

1. Outbox overflow spills to a JSONL file beside the sync log (no schema change, durable across restarts); `dropped: true` only for volatile mode (no `appliedSpillPath`) and IO failures — the flag stays honest. **Round 3**: spill mode is now write-through (append before `applyDelta` ack) + peek/ack (`sync:ackApplied` consumes only after the domain commit) — durability chosen over the reviewer's first alternative, and their second (rebuild from the durable log) is implemented too via `projectMaterialized`/`sync:materialized`.
2. `expo-secure-store` lazy-load inside `createExpoSync` (see Design choices).
3. Non-applied outcomes drop at the `applySyncedEntries` bound with a typed warn — re-projecting losers would resurrect divergence the merge already resolved.
4. `'sum'` writes assert the aggregate domain value; `writeChanges` stamps `target − remote share` as this device's component. The reviewer's alternative (track the local component separately) would require a second authoritative number next to every play-count row; stamping-at-write keeps the domain row itself the single source of truth.
5. New IPC surface on the existing `sync:*` contract, all validated + byte-budgeted: `sync:drainApplied` (peek), `sync:ackApplied` (offset advance), `sync:materialized` (paged materialized view), `sync:applied` (push), plus the session's `sync:localChanges` emit — a capability expansion in the same seam, flagged per the scope rule. The repo carries no `decisions.md` (AGENTS references a doc tree outside this checkout), so the row lives here.
